# 기능 명세서: 디지털 서예 웹앱

**프로젝트**: 디지털 서예 연습 및 AI 평가 시스템  
**생성일**: 2025-09-19  
**상태**: 요구사항 확정  
**타겟**: 성인 취미 입문자(20-40대) + 초등학생 한자 학습  
**학습 단위**: 1회 수업 = 10글자 완주 (시간 제한 없음)

## 서비스 개요

**"언제 어디서든 스마트폰으로 서예를 배우고, AI가 정확하게 평가해주는 디지털 서예 앱"**

- **성인 사용자**: 서예를 통한 힐링과 실력 향상을 위한 진지한 학습 도구
- **어린이 사용자**: 한자 학습을 재미있게 만드는 게임형 교육 앱
- **학습 방식**: 사용자가 설정한 글자 분량으로 학습 (기본 10글자, 조정 가능)
- **핵심 가치**: AI 기반 정확한 평가와 친근한 피드백으로 혼자서도 체계적 학습 가능

## 실행 흐름 (사용자 학습 과정)
```
1. 앱 실행 → 메인 화면 진입
2. 언어 선택 (한글 또는 한자)
3. 코스 선택 (다양한 학습 과정 중 선택)
4. 학습 분량 설정 (기본 10글자, 사용자가 조정 가능)
5. 설정된 분량만큼 글자 세트 시작
6. 글자별 연습 (터치/스타일러스로 그리기 또는 카메라 촬영)
7. AI 평가 및 피드백 확인
8. 다음 글자로 진행 (설정한 분량까지 반복)
9. 세트 완료 → 전체 결과 확인
10. 진도 저장 및 다음 세트 추천
```

## 사용자 시나리오 및 테스트 *(필수)*

### 주요 사용자 스토리
사용자는 두 가지 방식으로 서예를 연습할 수 있다: 
1) **실물 서예 연습** (메인): 종이에 붓으로 쓴 글자를 카메라로 촬영하여 평가
2) **디지털 연습** (보조): 캔버스에 손가락/스타일러스로 직접 그리기

시스템은 사용자의 입력을 표준 서예 작품과 비교하여 형태(40%), 비례(30%), 획의 굵기(20%), 획순(10%)을 평가하고 100점 만점 점수와 구체적인 개선 피드백을 제공한다.

### 실물 서예 평가 워크플로우 (핵심)
1. **학습 글자 선택**: 한글/한자 커리큘럼에서 연습할 글자 선택
2. **표준 글자 확인**: 표준 서예 작품을 참고하여 올바른 형태 학습
3. **실물 연습**: 종이에 붓으로 글자 작성
4. **카메라 촬영**: 스마트폰으로 작성한 글자 촬영
5. **AI 평가**: 이미지 분석을 통한 자동 평가 (Canvas API → LLM 확장)
6. **피드백 수령**: 점수 및 구체적인 개선 사항 확인
7. **진도 기록**: 개인 포트폴리오에 결과 저장

### 수용 시나리오
1. **조건** 사용자가 앱을 처음 실행했을 때, **동작** 언어(한글/한자)와 관심 분야를 선택하면, **결과** 개인 맞춤형 코스 추천과 학습 분량 설정 화면을 제공한다
2. **조건** 사용자가 코스를 선택했을 때, **동작** 학습 분량(기본 10글자)을 설정하면, **결과** 해당 분량의 글자들과 예쁜 샘플을 보여주며 학습을 시작한다
3. **조건** 사용자가 화면에 글자를 그렸을 때, **동작** 완료 버튼을 누르면, **결과** 기본적인 형태/비례 평가와 격려 메시지를 즉시 제공한다
4. **조건** 사용자가 종이에 쓴 글자를 촬영했을 때, **동작** 업로드하면, **결과** 서법 데이터 기반 AI가 상세한 피드백과 개선 방안을 친근하게 제시한다
5. **조건** 사용자가 설정한 분량을 완주했을 때, **동작** 세트 완료하면, **결과** 전체 학습 결과와 성취감을 주는 진도 표시, 다음 추천 학습을 제공한다

## 요구사항 *(필수)*

### 기능 요구사항

#### 사용자 경험 및 접근성
- **FR-001**: 시스템은 소셜 로그인을 통한 최소한의 회원가입으로 개인 맞춤형 학습 관리를 제공해야 한다
- **FR-002**: 시스템은 오프라인 상태에서도 연습 및 진도 저장 기능을 제공해야 한다
- **FR-003**: 시스템은 스마트폰을 주요 디바이스로 최적화되어야 한다 (태블릿 지원)
- **FR-004**: 사용자는 학습 분량(기본 10글자)을 개인 선호에 맞게 조정할 수 있어야 한다

#### 핵심 서비스 콘텐츠
- **FR-005**: 주요 서비스 콘텐츠는 한글 서예와 한자 서예 학습이다
- **FR-006**: 시스템은 다양한 학습 코스를 제공해야 한다 (내용은 추후 확장 가능)
- **FR-007**: 한글 서예 콘텐츠는 성인 대상 시/속담/좋은 글귀를 포함해야 한다
- **FR-008**: 한자 서예 콘텐츠는 초등학생 대상 기초 한자, 급수별, 교과서 연계를 포함해야 한다

#### 연습 및 입력 방식
- **FR-009**: 시스템은 터치 및 스타일러스를 이용한 화면 그리기를 지원해야 한다
- **FR-010**: 시스템은 카메라를 이용한 종이 글씨 촬영 업로드를 지원해야 한다
- **FR-011**: 화면 그리기는 기본적인 형태와 비례 평가를 제공해야 한다
- **FR-012**: 종이 촬영은 서법 데이터 기반 AI의 상세한 평가를 제공해야 한다

#### 평가 및 피드백
- **FR-013**: 시스템은 친근하고 격려하는 톤으로 피드백을 제공해야 한다
- **FR-014**: 점수는 내부 데이터로만 사용하고, 사용자에게는 정성적 평가를 제공해야 한다
- **FR-015**: AI 평가는 제공된 서법 데이터와 샘플 글자를 기준으로 수행되어야 한다
- **FR-016**: 평가 결과는 구체적인 개선 방안과 잘한 점을 함께 제시해야 한다

#### 진도 관리 및 학습 지원
- **FR-017**: 시스템은 사용자의 학습 진도를 시각적으로 표시해야 한다
- **FR-018**: 시스템은 완주한 세트에 대한 성취감을 주는 피드백을 제공해야 한다
- **FR-019**: 시스템은 사용자의 수준과 선호에 맞는 다음 학습을 추천해야 한다
- **FR-020**: 시스템은 오랜 시간 사용하지 않은 사용자의 재시작을 도와야 한다

#### 기술적 요구사항
- **FR-021**: 시스템은 저렴한 상용 LLM 서비스(GPT-3.5, Claude Haiku 등)를 사용해야 한다
- **FR-022**: LLM은 촬영 이미지 분석에만 제한적으로 사용되어야 한다
- **FR-023**: 시스템은 LLM 사용량을 제한하여 비용을 관리해야 한다
- **FR-024**: 화면 그리기 평가는 기존 Canvas API 기반 알고리즘으로 충분히 처리해야 한다

#### 진도 관리
- **FR-015**: 시스템은 사용자의 연습 기록을 저장해야 한다
- **FR-016**: 사용자는 이전 연습 결과와 비교하여 향상도를 확인할 수 있어야 한다
- **FR-017**: 시스템은 학습 통계와 진도를 추적해야 한다

#### 기술 요구사항
- **FR-018**: 시스템은 256레벨 압력 감지 기능이 있는 터치/스타일러스 입력을 지원해야 한다
- **FR-019**: 시스템은 2초 이내에 평가를 완료해야 한다
- **FR-020**: 시스템은 카메라 권한을 우아하게 처리하고 대체 메시지를 제공해야 한다
- **FR-021**: 시스템은 카메라 촬영용으로 JPEG 이미지 형식을 지원해야 한다
- **FR-022**: 시스템은 모바일과 데스크톱 기기 모두에서 작동해야 한다
- **FR-023**: 시스템은 캔버스 그림과 카메라 사진을 평가를 위해 일관된 형식으로 정규화해야 한다

#### 관리자 및 작품 관리 (MVP 확장)
- **FR-024**: 관리자는 서예 작가의 표준 작품을 시스템에 업로드할 수 있어야 한다
- **FR-025**: 관리자는 등록된 작품을 글자별/서체별로 활성화/비활성화할 수 있어야 한다
- **FR-026**: 시스템은 활성화된 작품을 사용자 평가의 기준으로 사용해야 한다
- **FR-027**: 시스템은 촬영된 이미지와 표준 작품을 비교하여 동일한 평가 체계(100점)로 점수를 산출해야 한다

### 핵심 엔티티 *(데이터 관련)*
- **연습세션(WritingSession)**: 사용자의 글자 쓰기 세션, 시작/종료 시간, 연습한 글자 목록, 선택한 서체
- **글자(Character)**: 연습 대상 글자, 서체별 표준 형태, 획순 정보, 평가 기준
- **작성시도(WritingAttempt)**: 개별 글자 작성 시도, 작성 시간, 획 데이터, 평가 결과
- **피드백(Feedback)**: 평가 결과에 따른 피드백, 요소별 점수, 개선 사항, 시각적 가이드
- **진도(Progress)**: 사용자의 학습 진도, 향상도 추적, 통계 정보
- **서체(FontStyle)**: 지원 서체 정보, 서체별 평가 가중치, 특성 데이터
- **학습과정(Course)**: 기초한자, 천자문, 사자소학 등 학습 커리큘럼
- **서예작품(CalligraphyArtwork)**: 관리자가 등록한 표준 서예 작품, 평가 기준으로 사용
- **카메라캡처(CameraCapture)**: 사용자가 촬영한 글자 이미지, 작품 기반 평가용
- **관리자(Admin)**: 시스템 관리자, 작품 등록 및 관리 권한

### 비기능 요구사항 (UX/접근성/테마)
- **NFR-001**: 텍스트 대비는 WCAG 2.1 AA(일반 텍스트 ≥ 4.5:1)를 충족해야 한다. 핵심 버튼 변형의 기본/hover/active 상태에 적용한다.
- **NFR-002**: UI는 디자인 토큰(`packages/ui/design/tokens.css`) 기반으로 색상/라디우스/섀도우를 일관되게 사용해야 한다. 하드코딩 색상은 지양한다.
- **NFR-003**: 컴포넌트는 shadcn/ui 스타일 가이드를 따르며, 토큰 브리지(`apps/web/src/styles/tokens-bridge.css`)를 통해 Tailwind 변수와 연결되어야 한다.
- **NFR-004**: 다크 테마 토큰 세트를 제공해야 하며, 런타임 토글 시 핵심 화면 시인성(AA)을 유지해야 한다.
- **NFR-005**: 화면 전환 및 상호작용은 키보드 조작 가능해야 하며, 포커스 링/링 색상은 테마 변수(`--ring`)로 표시되어야 한다.

## Phase 2: 기존 UI와 백엔드 통합 요구사항

### 통합 개요
기존 Figma 기반으로 제작된 고품질 UI (`calligraphy-coach` 폴더)와 우리가 개발한 백엔드 시스템(`apps/web` 폴더)을 통합하여 완전한 서예 앱을 구현한다.

### 통합 범위
- **UI 기반**: 기존 `calligraphy-coach` 폴더의 완성된 UI 활용
- **백엔드 연동**: 우리 개발 소스(`apps/web/src`)의 인증/스토리지/평가 시스템 연동
- **데이터 교체**: 하드코딩된 임시 데이터를 실제 API 호출로 교체
- **평가 시스템**: Canvas API + LLM 평가 시스템 통합

### 기능 요구사항 (통합 전용)

#### 인증 시스템 통합
- **FR-101**: 기존 UI의 AuthContext를 우리 소셜 로그인 시스템으로 교체해야 한다
- **FR-102**: Google/Apple/Kakao 소셜 로그인을 기존 UI 컴포넌트에 연동해야 한다
- **FR-103**: 로그인 상태 관리를 우리 useAuth 훅으로 일치시켜야 한다

#### 데이터 레이어 통합
- **FR-104**: 기존 UI의 하드코딩된 사용자 데이터를 실제 API로 교체해야 한다
- **FR-105**: localStorage 기반 데이터를 IndexedDB + 백엔드 연동으로 변경해야 한다
- **FR-106**: 연습 세션 데이터를 우리 WritingSession 엔티티 구조로 매핑해야 한다

#### Canvas 통합
- **FR-107**: 기존 UI의 PracticeScreen Canvas를 우리 stroke-capture 패키지로 교체해야 한다
- **FR-108**: 획 데이터 수집 및 압력 감지 기능을 통합해야 한다
- **FR-109**: Canvas 그리기 평가를 우리 character-recognition 시스템으로 연동해야 한다

#### LLM 평가 통합
- **FR-110**: 카메라 촬영 기능을 우리 LLM 평가 시스템과 연동해야 한다
- **FR-111**: 평가 결과 표시를 우리 평가 기준 (8개 항목)에 맞게 수정해야 한다
- **FR-112**: LLM 폴백 시스템을 기존 UI 플로우에 자연스럽게 통합해야 한다

#### 진도 관리 통합
- **FR-113**: 기존 UI의 진도 표시를 우리 Progress 엔티티 기반으로 동작하게 해야 한다
- **FR-114**: 통계 차트 데이터를 실제 사용자 연습 기록에서 가져와야 한다
- **FR-115**: 최고 기록 위젯을 실제 사용자 성취 데이터와 연동해야 한다

### 기술 통합 요구사항
- **FR-116**: Tailwind CSS v4 (기존 UI) ↔ v3 (우리 시스템) 호환성 확보
- **FR-117**: shadcn/ui 컴포넌트를 우리 디자인 토큰과 통합
- **FR-118**: 기존 UI의 라우팅을 우리 앱 구조와 일치시키기
- **FR-119**: 젠 스타일 디자인 시스템을 우리 브랜드 가이드라인과 조화

### 데이터 마이그레이션 요구사항
- **FR-120**: 기존 UI 임시 데이터 구조 분석 및 우리 엔티티로 매핑 테이블 작성

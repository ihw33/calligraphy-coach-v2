# 기능 명세서: 필기 인식 및 피드백 시스템

**기능 브랜치**: `001-`  
**생성일**: 2025-09-12  
**상태**: 초안  
**입력**: 사용자 설명: "사용자가 직접 쓴 한자나 한글을 인식하고 어느 정도 제대로 썼는지 평가하고 피드백을 준다"

## 실행 흐름 (main)
```
1. 입력에서 사용자 설명 파싱
   → 비어있으면: 오류 "기능 설명이 제공되지 않음"
2. 설명에서 핵심 개념 추출
   → 식별: 행위자, 동작, 데이터, 제약사항
3. 불명확한 각 측면에 대해:
   → [명확화 필요: 구체적 질문]으로 표시
4. 사용자 시나리오 및 테스트 섹션 작성
   → 명확한 사용자 흐름이 없으면: 오류 "사용자 시나리오를 결정할 수 없음"
5. 기능 요구사항 생성
   → 각 요구사항은 테스트 가능해야 함
   → 모호한 요구사항 표시
6. 핵심 엔티티 식별 (데이터 관련시)
7. 검토 체크리스트 실행
   → [명확화 필요] 항목이 있으면: 경고 "명세에 불확실성 있음"
   → 구현 세부사항이 발견되면: 오류 "기술 세부사항 제거"
8. 반환: 성공 (명세 계획 준비 완료)
```

## 사용자 시나리오 및 테스트 *(필수)*

### 주요 사용자 스토리
사용자는 두 가지 방식으로 서예를 연습할 수 있다: 
1) **실물 서예 연습** (메인): 종이에 붓으로 쓴 글자를 카메라로 촬영하여 평가
2) **디지털 연습** (보조): 캔버스에 손가락/스타일러스로 직접 그리기

시스템은 사용자의 입력을 표준 서예 작품과 비교하여 형태(40%), 비례(30%), 획의 굵기(20%), 획순(10%)을 평가하고 100점 만점 점수와 구체적인 개선 피드백을 제공한다.

### 실물 서예 평가 워크플로우 (핵심)
1. **학습 글자 선택**: 한글/한자 커리큘럼에서 연습할 글자 선택
2. **표준 글자 확인**: 표준 서예 작품을 참고하여 올바른 형태 학습
3. **실물 연습**: 종이에 붓으로 글자 작성
4. **카메라 촬영**: 스마트폰으로 작성한 글자 촬영
5. **AI 평가**: 이미지 분석을 통한 자동 평가 (Canvas API → LLM 확장)
6. **피드백 수령**: 점수 및 구체적인 개선 사항 확인
7. **진도 기록**: 개인 포트폴리오에 결과 저장

### 수용 시나리오
1. **조건** 사용자가 연습할 글자를 선택했을 때, **동작** "캔버스 그리기" 모드를 선택하고 화면에 글자를 그리면, **결과** 시스템이 실시간으로 획을 캡처하고 표준 작품과 비교하여 점수를 제공한다
2. **조건** 사용자가 연습할 글자를 선택했을 때, **동작** "카메라 촬영" 모드를 선택하고 종이에 쓴 글자를 촬영하면, **결과** 시스템이 이미지를 처리하고 표준 작품과 비교하여 동일한 평가 기준으로 점수를 제공한다
3. **조건** 사용자가 입력을 완료했을 때, **동작** 평가를 요청하면, **결과** 시스템이 형태(40%), 비례(30%), 굵기(20%), 획순(10%)별 세부 점수와 100점 만점 총점을 2초 이내에 표시한다
4. **조건** 사용자가 입력 방식을 바꾸고 싶을 때, **동작** 캔버스/카메라 모드를 전환하면, **결과** 시스템이 글자 선택을 유지하면서 해당 입력 인터페이스를 표시한다
5. **조건** 사용자가 연습을 반복할 때, **동작** 여러 번 시도하면, **결과** 시스템이 진도를 추적하고 이전 점수와 비교하여 향상도를 보여준다

### 엣지 케이스
- 사용자가 알아볼 수 없는 글자를 작성했을 때 어떻게 처리할 것인가?
- 여러 글자를 동시에 작성했을 때 시스템이 어떻게 처리할 것인가?
- 글자가 화면 밖으로 벗어났을 때 어떻게 처리할 것인가?
- 필기 도구가 너무 얇거나 두꺼울 때 시스템이 어떻게 처리할 것인가?

## 요구사항 *(필수)*

### 기능 요구사항

#### 서체 지원
- **FR-001**: 시스템은 한글 판본체와 궁서체를 지원해야 한다
- **FR-002**: 시스템은 한자 전서체와 해서체를 지원해야 한다
- **FR-003**: 사용자는 연습할 서체를 선택할 수 있어야 한다

#### 평가 기준
- **FR-004**: 시스템은 형태(40점), 비례(30점), 굵기(20점), 획순(10점)으로 100점 만점 체계로 평가해야 한다
- **FR-005**: 시스템은 각 획의 순서가 올바른지 판단해야 한다
- **FR-006**: 시스템은 결구(형태, 비례, 선 굵기)를 분석해야 한다
- **FR-007**: 시스템은 선택된 서체의 특성에 맞게 평가 기준을 조정해야 한다

#### 학습 콘텐츠
- **FR-008**: 시스템은 한글 낱자와 단어를 지원해야 한다
- **FR-009**: 시스템은 기초한자 600자와 1200자 과정을 제공해야 한다
- **FR-010**: 시스템은 천자문과 사자소학 학습 과정을 제공해야 한다

#### 인식 및 피드백
- **FR-011**: 시스템은 사용자가 작성한 글자를 실시간으로 인식해야 한다
- **FR-012**: 시스템은 글자 샘플과의 일치 정도를 비교하여 점수를 산출해야 한다
- **FR-013**: 시스템은 개선이 필요한 부분을 시각적으로 표시해야 한다
- **FR-014**: 사용자는 평가 결과를 점수와 함께 각 평가 요소별로 확인할 수 있어야 한다

#### 평가 시스템 (단계별 구현)
- **FR-028**: **1단계 평가**: 시스템은 Canvas API를 사용하여 기본적인 픽셀 비교 평가를 제공해야 한다
- **FR-029**: **2단계 평가**: 시스템은 LLM을 활용하여 전문가 수준의 서예 평가를 제공해야 한다
- **FR-030**: **LLM 요청 템플릿**: 시스템은 구조화된 프롬프트를 사용하여 일관성 있는 평가를 요청해야 한다
- **FR-031**: **LLM 응답 형식**: 시스템은 JSON 형태의 구조화된 평가 결과를 받아 처리해야 한다
- **FR-032**: **피드백 품질**: LLM 평가는 구체적이고 실행 가능한 개선 방안을 포함해야 한다

#### 진도 관리
- **FR-015**: 시스템은 사용자의 연습 기록을 저장해야 한다
- **FR-016**: 사용자는 이전 연습 결과와 비교하여 향상도를 확인할 수 있어야 한다
- **FR-017**: 시스템은 학습 통계와 진도를 추적해야 한다

#### 기술 요구사항
- **FR-018**: 시스템은 256레벨 압력 감지 기능이 있는 터치/스타일러스 입력을 지원해야 한다
- **FR-019**: 시스템은 2초 이내에 평가를 완료해야 한다
- **FR-020**: 시스템은 카메라 권한을 우아하게 처리하고 대체 메시지를 제공해야 한다
- **FR-021**: 시스템은 카메라 촬영용으로 JPEG 이미지 형식을 지원해야 한다
- **FR-022**: 시스템은 모바일과 데스크톱 기기 모두에서 작동해야 한다
- **FR-023**: 시스템은 캔버스 그림과 카메라 사진을 평가를 위해 일관된 형식으로 정규화해야 한다

#### 관리자 및 작품 관리 (MVP 확장)
- **FR-024**: 관리자는 서예 작가의 표준 작품을 시스템에 업로드할 수 있어야 한다
- **FR-025**: 관리자는 등록된 작품을 글자별/서체별로 활성화/비활성화할 수 있어야 한다
- **FR-026**: 시스템은 활성화된 작품을 사용자 평가의 기준으로 사용해야 한다
- **FR-027**: 시스템은 촬영된 이미지와 표준 작품을 비교하여 동일한 평가 체계(100점)로 점수를 산출해야 한다

### 핵심 엔티티 *(데이터 관련)*
- **연습세션(WritingSession)**: 사용자의 글자 쓰기 세션, 시작/종료 시간, 연습한 글자 목록, 선택한 서체
- **글자(Character)**: 연습 대상 글자, 서체별 표준 형태, 획순 정보, 평가 기준
- **작성시도(WritingAttempt)**: 개별 글자 작성 시도, 작성 시간, 획 데이터, 평가 결과
- **피드백(Feedback)**: 평가 결과에 따른 피드백, 요소별 점수, 개선 사항, 시각적 가이드
- **진도(Progress)**: 사용자의 학습 진도, 향상도 추적, 통계 정보
- **서체(FontStyle)**: 지원 서체 정보, 서체별 평가 가중치, 특성 데이터
- **학습과정(Course)**: 기초한자, 천자문, 사자소학 등 학습 커리큘럼
- **서예작품(CalligraphyArtwork)**: 관리자가 등록한 표준 서예 작품, 평가 기준으로 사용
- **카메라캡처(CameraCapture)**: 사용자가 촬영한 글자 이미지, 작품 기반 평가용
- **관리자(Admin)**: 시스템 관리자, 작품 등록 및 관리 권한

## LLM 연동 상세 명세 *(2단계 확장)*

### LLM 평가 요청 템플릿
```json
{
  "system_prompt": "당신은 30년 경력의 서예 전문가입니다. 사용자가 제출한 서예 작품을 전문적으로 평가해주세요.",
  "user_prompt": {
    "image": "[BASE64_ENCODED_IMAGE]",
    "target_character": "人",
    "font_style": "해서체",
    "evaluation_criteria": {
      "형태": "표준 글자와의 전체적인 형태 일치도 (40%)",
      "비례": "각 부분 간의 균형과 비례 관계 (30%)", 
      "굵기": "획의 굵기와 농담 표현 (20%)",
      "획순": "올바른 획순에 따른 자연스러운 흐름 (10%)"
    },
    "instruction": "각 평가 기준별로 구체적인 점수와 개선 사항을 제시해주세요."
  }
}
```

### LLM 연동 기술 요구사항
- **FR-033**: 시스템은 이미지를 Base64로 인코딩하여 LLM에 전송해야 한다
- **FR-034**: LLM 응답 처리 시간은 10초를 초과하지 않아야 한다
- **FR-035**: LLM 연동 실패 시 Canvas API 기본 평가로 대체해야 한다
- **FR-036**: 평가 결과는 일관성을 위해 표준화된 JSON 스키마를 따라야 한다
- **FR-037**: 민감한 API 키는 환경변수로 관리되어야 한다

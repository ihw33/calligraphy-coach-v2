# 연구 문서: 붓글씨 인식 및 피드백 시스템

## 확인된 연구 영역

### 1. 붓글씨 입력 기술 스택
**결정**: Canvas API + Pointer Events API + Pressure API
**근거**: 
- Canvas API는 웹 표준으로 붓글씨의 자유로운 획 표현 가능
- Pointer Events API로 펜/터치 입력의 압력 감지 지원
- 압력 데이터로 붓의 굵기와 농담 표현 구현 가능
**검토한 대안**:
- SVG: 벡터 기반이지만 실시간 붓글씨 표현에 제한적
- WebGL: 성능은 우수하나 복잡도가 높음

### 2. 한글/한자 인식 라이브러리
**결정**: TensorFlow.js + 사전 학습된 한글/한자 모델
**근거**:
- 브라우저에서 직접 실행 가능 (서버 불필요)
- 한글/한자 특화 모델 활용 가능
- 실시간 인식 성능 확보
**검토한 대안**:
- Google Cloud Vision API: 서버 의존성, 비용 발생
- Tesseract.js: OCR 중심으로 붓글씨 인식 정확도 낮음

### 3. 서예 평가 알고리즘
**결정**: 커스텀 평가 엔진 (획순 + 형태 분석)
**근거**:
- 서예 특화 평가 기준 필요 (형태 40%, 비례 30%, 굵기 20%, 획순 10%)
- 서체별 다른 평가 기준 적용 필요
- 표준 글자와의 비교 분석 필요
**검토한 대안**:
- 기존 OCR 신뢰도: 서예 미학 평가 불가
- 단순 이미지 유사도: 획순, 필압 등 고려 불가

### 4. 데이터 저장 방식
**결정**: IndexedDB + LocalStorage 하이브리드
**근거**:
- IndexedDB: 대용량 붓글씨 이미지와 획 데이터 저장
- LocalStorage: 설정, 진도 등 가벼운 데이터
- 오프라인 우선 지원
**검토한 대안**:
- 서버 DB: 초기 단계에서는 불필요한 복잡도
- WebSQL: 더 이상 사용되지 않음 (Deprecated)

### 5. 프레임워크 선택
**결정**: React + Next.js (기존 프로젝트 구조 활용)
**근거**:
- 프로젝트에 이미 설정되어 있음
- Canvas 조작과 React 컴포넌트 통합 용이
- 성능 최적화 도구 제공
**검토한 대안**:
- Vanilla JS: 프로젝트 일관성 부족
- Vue/Angular: 마이그레이션 비용

### 6. 테스트 전략
**결정**: Vitest + Testing Library + Playwright
**근거**:
- Vitest: 빠른 단위 테스트
- Testing Library: 컴포넌트 테스트
- Playwright: 실제 펜 입력 시뮬레이션 E2E
**검토한 대안**:
- Jest: Vitest가 더 빠름
- Cypress: 펜 입력 시뮬레이션 제한적

## 기술 스택 요약

### 프론트엔드
- **프레임워크**: React 18+ with Next.js 14+
- **언어**: TypeScript 5+
- **그리기**: Canvas API + Pointer Events
- **상태 관리**: Zustand (가벼운 상태 관리)
- **스타일링**: Tailwind CSS

### 인식 및 평가
- **ML 프레임워크**: TensorFlow.js
- **문자 모델**: 사전 학습된 한글/한자 모델
- **평가**: 서예 측정을 위한 커스텀 알고리즘

### 저장소
- **주 저장소**: IndexedDB (획 데이터, 이미지)
- **보조 저장소**: LocalStorage (설정, 진도)
- **내보내기**: JSON/PNG 형식

### 개발 도구
- **테스팅**: Vitest, Testing Library, Playwright
- **빌드**: Turbo (모노레포)
- **린팅**: ESLint + Prettier
- **CI/CD**: GitHub Actions

## 세분화된 성능 목표

1. **입력 지연**: <16ms (60fps 유지)
2. **압력 샘플링**: 120Hz 이상
3. **문자 인식**: 문자당 <500ms
4. **평가 계산**: <200ms
5. **UI 응답**: <100ms

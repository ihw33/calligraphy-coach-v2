# 기능 명세서: 필기 인식 및 피드백 시스템

**기능 브랜치**: `003-canvas-api-llm`  
**생성일**: 2025-09-15  
**상태**: 완전 명세  
**입력**: 사용자 설명: "사용자가 직접 쓴 한자나 한글을 인식하고 어느 정도 제대로 썼는지 평가하고 피드백을 준다"

## AI 팀 구성 및 협업 체계

### Team A: Backend Engine Team (Claude Code)
**담당**: 핵심 라이브러리 및 평가 엔진
- stroke-capture, character-recognition, calligraphy-evaluator, feedback-generator
- Canvas API, LLM 연동, 데이터 모델, TDD 테스트

### Team B: Frontend App Team (Cursor ChatGPT)  
**담당**: React 앱 구현 및 통합
- React/Next.js 컴포넌트, 상태 관리, API 연동, 라우팅

### Team C: Design System Team (Figma AI)
**담당**: UI/UX 설계 및 디자인 시스템
- 화면 구성, 사용자 여정, 디자인 토큰, 프로토타이핑

### 협업 지점
- **[Team A+B]**: API 계약 및 데이터 스펙
- **[Team B+C]**: 컴포넌트 인터페이스 및 디자인 구현
- **[Team A+C]**: 사용자 플로우 및 성능 요구사항

## 실행 흐름 (main)
```
1. 입력에서 사용자 설명 파싱
   → 비어있으면: 오류 "기능 설명이 제공되지 않음"
2. 설명에서 핵심 개념 추출
   → 식별: 행위자, 동작, 데이터, 제약사항
3. 불명확한 각 측면에 대해:
   → [명확화 필요: 구체적 질문]으로 표시
4. 사용자 시나리오 및 테스트 섹션 작성
   → 명확한 사용자 흐름이 없으면: 오류 "사용자 시나리오를 결정할 수 없음"
5. 기능 요구사항 생성
   → 각 요구사항은 테스트 가능해야 함
   → 모호한 요구사항 표시
6. 핵심 엔티티 식별 (데이터 관련시)
7. 검토 체크리스트 실행
   → [명확화 필요] 항목이 있으면: 경고 "명세에 불확실성 있음"
   → 구현 세부사항이 발견되면: 오류 "기술 세부사항 제거"
8. 반환: 성공 (명세 계획 준비 완료)
```

## 사용자 시나리오 및 테스트 *(필수)*

### 최종 사용자 스토리 [Team B+C]
사용자는 두 가지 방식으로 서예를 연습할 수 있다: 
1) **실물 서예 연습** (메인): 종이에 붓으로 쓴 글자를 카메라로 촬영하여 평가
2) **디지털 연습** (보조): 캔버스에 손가락/스타일러스로 직접 그리기

시스템은 사용자의 입력을 표준 서예 작품과 비교하여 형태(40%), 비례(30%), 획의 굵기(20%), 획순(10%)을 평가하고 100점 만점 점수와 구체적인 개선 피드백을 제공한다.

### 개발자 워크플로우 스토리 [Team A+B+C]
개발팀은 AI 협업을 통해 서예 앱을 구축한다:
1) **[Team A]** MVP 분석 및 라이브러리 추출 → 독립적인 기능 모듈 생성
2) **[Team C]** 사용자 여정 설계 및 디자인 시스템 구축 → 화면 및 컴포넌트 스펙 생성  
3) **[Team B]** React 앱 구현 및 라이브러리 통합 → 완전한 서예 연습 앱 완성
4) **[Team A+B+C]** 통합 테스트 및 성능 최적화 → 배포 가능한 프로덕션 앱

### 완전한 앱 사용자 여정 [Team B+C]
#### 신규 사용자
1. **온보딩**: 앱 소개 → 서체 선택 → 연습 방식 안내 → 첫 글자 연습 가이드
2. **프로필 설정**: 학습 목표 설정 → 연습 빈도 선택 → 알림 설정
3. **첫 연습**: 간단한 글자 선택 → 연습 방식(캔버스/카메라) 선택 → 기본 평가 경험

#### 일반 사용자  
1. **일상 연습**: 로그인 → 오늘의 추천 글자 → 연습 → 즉시 평가 → 피드백 확인 → 진도 업데이트
2. **맞춤 학습**: 약점 분석 확인 → 개선 영역 집중 연습 → 반복 학습 → 향상도 추적
3. **도전 모드**: 고급 글자 도전 → 시간 제한 연습 → 정확도 경쟁 → 성취 배지 획득

#### 고급 사용자
1. **마스터리**: 전체 과정 완주 → 자유 창작 모드 → 작품 갤러리 구축 → 다른 사용자와 공유
2. **멘토링**: 후배 학습자 지도 → 피드백 제공 → 커뮤니티 활동

### 실물 서예 평가 워크플로우 (핵심)
1. **학습 글자 선택**: 한글/한자 커리큘럼에서 연습할 글자 선택
2. **표준 글자 확인**: 표준 서예 작품을 참고하여 올바른 형태 학습
3. **실물 연습**: 종이에 붓으로 글자 작성
4. **카메라 촬영**: 스마트폰으로 작성한 글자 촬영
5. **AI 평가**: 이미지 분석을 통한 자동 평가 (Canvas API → LLM 확장)
6. **피드백 수령**: 점수 및 구체적인 개선 사항 확인
7. **진도 기록**: 개인 포트폴리오에 결과 저장

### 수용 시나리오

#### 핵심 기능 시나리오 [Team A+B]
1. **조건** 사용자가 연습할 글자를 선택했을 때, **동작** "캔버스 그리기" 모드를 선택하고 화면에 글자를 그리면, **결과** 시스템이 실시간으로 획을 캡처하고 표준 작품과 비교하여 점수를 제공한다
2. **조건** 사용자가 연습할 글자를 선택했을 때, **동작** "카메라 촬영" 모드를 선택하고 종이에 쓴 글자를 촬영하면, **결과** 시스템이 이미지를 처리하고 표준 작품과 비교하여 동일한 평가 기준으로 점수를 제공한다
3. **조건** 사용자가 입력을 완료했을 때, **동작** 평가를 요청하면, **결과** 시스템이 형태(40%), 비례(30%), 굵기(20%), 획순(10%)별 세부 점수와 100점 만점 총점을 2초 이내에 표시한다

#### UI/UX 시나리오 [Team B+C]
4. **조건** 사용자가 처음 앱을 실행했을 때, **동작** 온보딩 플로우를 진행하면, **결과** 서체 선택, 연습 방식 안내, 첫 글자 연습까지 자연스럽게 가이드된다
5. **조건** 사용자가 입력 방식을 바꾸고 싶을 때, **동작** 캔버스/카메라 모드를 전환하면, **결과** 시스템이 글자 선택을 유지하면서 해당 입력 인터페이스를 표시한다
6. **조건** 사용자가 진도를 확인하고 싶을 때, **동작** 대시보드에 접근하면, **결과** 학습 통계, 향상도 차트, 성취 배지를 직관적으로 표시한다

#### 개발 워크플로우 시나리오 [Team A+B+C]
7. **조건** 개발자가 MVP 코드를 분석할 때, **동작** 기존 기능을 라이브러리별로 분리하면, **결과** 각 라이브러리가 독립적으로 테스트 가능하고 CLI를 제공한다
8. **조건** 개발자가 React 컴포넌트를 작성할 때, **동작** 기존 Canvas/카메라 로직을 재사용하면, **결과** 동일한 사용자 경험을 제공하면서 더 나은 코드 구조를 갖는다
9. **조건** 개발자가 라이브러리를 구현할 때, **동작** TDD 방식을 따르면, **결과** 모든 기능이 테스트로 검증되고 안정적으로 작동한다

#### 고급 기능 시나리오 [Team A+B+C]
10. **조건** 사용자가 연습을 반복할 때, **동작** 여러 번 시도하면, **결과** 시스템이 진도를 추적하고 이전 점수와 비교하여 향상도를 보여준다
11. **조건** 사용자가 고급 평가를 원할 때, **동작** LLM 평가를 요청하면, **결과** 전문가 수준의 상세한 피드백과 구체적인 개선 방안을 제공한다
12. **조건** 사용자가 오프라인 상태일 때, **동작** 기본 연습을 시도하면, **결과** Canvas API 기반 평가로 기본적인 피드백을 제공하고 온라인 복구 시 동기화한다

## 요구사항 *(필수)*

### 기능 요구사항

#### 핵심 서예 기능 [Team A+B+C]

##### 서체 지원 [Team A+C]
- **FR-001**: 시스템은 한글 판본체와 궁서체를 지원해야 한다
- **FR-002**: 시스템은 한자 전서체와 해서체를 지원해야 한다
- **FR-003**: 사용자는 연습할 서체를 선택할 수 있어야 한다
- **FR-004**: 각 서체는 고유한 시각적 특성과 평가 기준을 가져야 한다

##### 평가 기준 [Team A]
- **FR-005**: 시스템은 형태(40점), 비례(30점), 굵기(20점), 획순(10점)으로 100점 만점 체계로 평가해야 한다
- **FR-006**: 시스템은 각 획의 순서가 올바른지 판단해야 한다
- **FR-007**: 시스템은 결구(형태, 비례, 선 굵기)를 분석해야 한다
- **FR-008**: 시스템은 선택된 서체의 특성에 맞게 평가 기준을 조정해야 한다
- **FR-009**: 평가는 일관성 있고 재현 가능해야 한다

##### 학습 콘텐츠 [Team A+C]
- **FR-010**: 시스템은 한글 낱자와 단어를 지원해야 한다
- **FR-011**: 시스템은 기초한자 600자와 1200자 과정을 제공해야 한다
- **FR-012**: 시스템은 천자문과 사자소학 학습 과정을 제공해야 한다
- **FR-013**: 글자는 난이도별로 분류되어야 한다 (초급/중급/고급)
- **FR-014**: 각 글자마다 표준 서예 작품 샘플을 제공해야 한다

#### 기술 구현 요구사항 [Team A]

##### 입력 및 인식 [Team A+B]
- **FR-015**: 시스템은 사용자가 작성한 글자를 실시간으로 인식해야 한다
- **FR-016**: 시스템은 Canvas API를 통한 디지털 입력을 지원해야 한다
- **FR-017**: 시스템은 카메라를 통한 실물 서예 입력을 지원해야 한다
- **FR-018**: 압력 감지 기능이 있는 터치/스타일러스 입력을 지원해야 한다 (256 레벨)
- **FR-019**: 시스템은 획 순서와 방향을 추적해야 한다

##### 평가 엔진 [Team A] 
- **FR-020**: **1단계 평가**: Canvas API를 사용한 기본적인 픽셀 비교 평가
- **FR-021**: **2단계 평가**: LLM을 활용한 전문가 수준의 서예 평가
- **FR-022**: **LLM 요청 템플릿**: 구조화된 프롬프트로 일관성 있는 평가 요청
- **FR-023**: **LLM 응답 형식**: JSON 형태의 구조화된 평가 결과 처리
- **FR-024**: **피드백 품질**: 구체적이고 실행 가능한 개선 방안 포함
- **FR-025**: **폴백 메커니즘**: LLM 실패 시 Canvas API로 자동 전환

##### 데이터 처리 [Team A]
- **FR-026**: 이미지를 Base64로 인코딩하여 LLM에 전송해야 한다
- **FR-027**: 이미지 압축 및 최적화로 전송 크기를 최소화해야 한다
- **FR-028**: 캔버스 그림과 카메라 사진을 일관된 형식으로 정규화해야 한다
- **FR-029**: 획 데이터를 구조화된 형태로 저장해야 한다

#### 라이브러리 아키텍처 [Team A]

##### 핵심 라이브러리 [Team A]
- **FR-030**: **stroke-capture 라이브러리**: Canvas API와 Pointer Events 추상화
- **FR-031**: **character-recognition 라이브러리**: TensorFlow.js 모델 로드 및 추론
- **FR-032**: **calligraphy-evaluator 라이브러리**: Canvas API와 LLM 평가 통합
- **FR-033**: **feedback-generator 라이브러리**: 평가 결과를 구조화된 피드백으로 변환
